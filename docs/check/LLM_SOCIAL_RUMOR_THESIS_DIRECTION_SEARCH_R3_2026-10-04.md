# UMER 第二毕业论文工作：完整研究主线的第三轮评估

研究检索截至：2026-10-04。整理性质：选题讨论，不是立项、实验授权或创新保证。

## 1. 核心结论

本轮不再把局部现象包装成完整第二工作。比较了三个完整任务：不可信社会上下文下的安全谣言研判、谣言活动的协调放大发现、跨帖共享核查与预算调度。

**当前没有一个可以诚实地称为“创新已核实、数据已就绪、可立即开做”的方案。** 这不证明领域没有空间；它说明本轮发现的近邻和数据缺口，不允许直接宣布成功选题。

最值得与用户讨论的是安全研判主线，但不应直接主推立项。它最贴近网安和已有资产，却仍属于认证鲁棒性研究。只有用户接受“研究可证明的安全属性，而非仅提高鲁棒精度”，且后续确认有实质方法差异，才值得继续。若用户连这一任务类型也不接受，应停止扩写该线，而不是继续换名。

另外两线具有独立任务形态，但数据与 UMER 实质承接尚不成立，暂作条件备选，不建议拼接数据开实验。

本轮不重推用户已否定的数值/时间范围核验、parent/root立场组合、同图属性充分性、无依据组合与跨agent放大防御。历史报告的排序不是当前推荐。

## 2. 第二工作应满足的标准

1. 社交网络谣言是核心研究对象，不是普通安全方法的随意应用示例。
2. 能独立定义输入、输出、研究问题、方法和评价；不只给 UMER 加特征或改损失。
3. LLM 承担语义理解/推理职能，并与强非LLM基线比较；不能预先宣称不可替代。
4. UMER 的承接可以是任务、数据协议和冻结系统，而不必复用全部模块；但仅把它放在流程开头，不能算实质方法联系。
5. 数据标签真正支持研究结论；不以 helpfulness 替代 truth，不以 IO 账号标签替代每帖恶意谣言标签。
6. 研究贡献可证伪、有强近邻对照、有现实资源路径；不能保证发表。
7. 仿真只能支持受控环境结论，不能冒充真实社会干预收益。

UMER 已提供事件级源帖与回复树、文本/图编码、训练折检索以及事件隔离协议。其 PHEME 消融中图移除约损失0.48个百分点、检索移除约0.03个百分点、文本移除约3.88个百分点。因此不能先验声称图已经具有强事实推理或治理作用。第二工作若需要关键图贡献，必须另行证明。

## 3. 候选A：面向受操纵社会上下文的 LLM 谣言研判

### 3.1 完整任务，而不是鲁棒训练配件

暂定讨论题名：**结构依赖下的 LLM 社交谣言研判安全认证**。

输入：固定时间截面的源帖、回复文本及可核查的回复/转发关系与时间元数据。

输出：任务标签或不判定、限定输入操纵范围下的决策稳定性证书、可回放的输入引用记录。

第一工作回答“如何融合事件信息进行谣言检测”；第二工作回答“当社会输入不可信时，系统在什么条件下仍能给出有边界的稳定决策，何时不能作确定判断”。

注意：使用 UMER 的 rumor/non-rumor 协议时，不能改称 false/true 事实核验；研究真假必须使用另行核实的 veracity gold。不判定是一种系统动作，不等同于数据标签 unverified。

### 3.2 可研究的方法位置

LLM 对隔离的局部讨论片段读取源帖相关信息；防御层建模同一条回复通过父子上下文、重叠片段、引用关系影响多个读取结果的依赖，限制影响传播，并构造可分析的聚合决策。

**这只是方法假设，尚未实现或证明。** 不采用“每个回复投一票，多数就是事实”的推理。认证也不要求把所有回复当统计独立；输入依赖、模型调用依赖、统计独立性是不同概念。

潜在贡献必须超出“算出最多影响多少片段，再套现成投票证书”。例如，在明确条件下得到非显然且更紧的结构认证界，或者更有用的安全决策机制；不能只用更复杂名字表示污染预算重参数化。

固定元数据不是天然可信。历史缓存、边构造、身份标识与截面边界尚需审计。账号不等于真实控制实体，不能假设同作者分组就能覆盖 Sybil 操纵。文本决定的全局聚类也可能被单条输入重写，破坏有限影响假设。

引用记录只能证明“系统用了哪些已记录输入”，不能证明输入内容真实、来源诚实或传播边具有因果真实性。文本重复/共享URL也不自动证明共同事实来源。

### 3.4 UMER 如何承接，及其限制

冻结 UMER 可作为现有事件检测系统、受污染表现参照和多读出测试平台；继承事件隔离与历史数据处理经验。第二工作不能只是把 UMER 输出交给 LLM 改判。

如果未经认证的 UMER 全树分数仍参与最终标签，证书必须覆盖这个路径。不能一边保留任意全树输入影响，一边只认证LLM聚合器后宣称整系统安全。若隔离掉该路径，需要检验任务效用是否仍足够；这也是承接强度的真实风险。

不要求复制第一工作的全部架构，但若用户要求方法上直接复用UMER核心，此候选目前并未满足。

### 3.5 评价与否决条件

必要对照：冻结UMER、source-only reader、简单删除回复/去重、SINCon类防御、RobustRAG直接迁移与结构无关认证聚合；近邻实施前另查代码/许可/预算。

主评价联合报告：
- certified-correct coverage：被认证且标签正确的比例；与纯认证率分开。
- clean accuracy、明确覆盖率下的 selective risk、拒判率与污染预算曲线。
- 合法新纠正信息的响应能力，避免把一切社会信息都屏蔽而获胜。
- 调用次数、延迟、显存与吞吐；引用记录完整性可作辅助，不是新的事实证书。

强否决：
1. 只得到现成方法迁移或预算上界替换，没有实质贡献。
2. 靠源帖恒定预测/大量拒判获得认证，任务效用不足。
3. 威胁边界无法在数据中落实，或完整决策路径超出证书。
4. 社会关系上下文没有可复现的额外价值，source-only已覆盖主要收益。

没有预设“80%拒判”等未经论证阈值。具体效用门槛应在观察确认集前注册，不能看完结果再挑。

计算路径初步可考虑缓存少量片段读出、7/8B低比特推理；单共享4090可行性只是工程估计，尚未实测。LOCAL不加载7/8B模型。本轮不生成攻击payload，不优化规避策略，不对第三方系统测试；未来只在用户授权的离线防御评测范围内推进。

**当前决策：值得讨论，不是推荐立即立项。先确认用户是否接受“安全属性研究”的任务形态。**

## 4. 候选B：谣言事件驱动的协调放大活动发现

输入某个已核实谣言事件的跨帖信息与账号交互；输出与该谣言相关的协调群组、可复核关联和未知拒识。目标是群组/活动发现，不是人物政治意图归因或换一个帖子分类器。

LLM的潜在作用是区分主张传播、报道引用与纠正，归并事件相关表达；图层检测跨帖时序与共同互动。UMER可以提供事件级检测资产，但若只作初始过滤，方法承接仍偏弱。

### 4.1 强近邻

- [Unmasking the Web of Deceit，WWW2024原文](https://arxiv.org/html/2310.09884v1)：多种行为痕迹、融合与网络表示检测协调活动；多视图图融合并非空白。
- [Network-informed Prompt Engineering，WWW2025 Companion原文](https://arxiv.org/html/2501.11849)：网络信息转文本、frozen LLM、Balanced RAG与不平衡检测。原文部分传播父边由关系推断/随机补全，不能当真实传播来源gold。
- [X-Troll，CIKM2025原文](https://arxiv.org/html/2508.16021)：账号检测、campaign分类与可解释rationale。检测+解释不能直接构成新贡献。
- [FakeCTI，原文v2](https://arxiv.org/html/2505.03345v2)：LLM语义概念/三元组与已知campaign归属。文章级CTI不自动等于社交谣言传播溯源。
- [DISINFOX原文](https://arxiv.org/html/2502.20997v1)：DISARM/STIX2与CTI互操作。增加处置模板或情报格式不等于新任务或真实干预效果。
- [UNLP2026工作坊论文](https://aclanthology.org/2026.unlp-1.9/)：已有语义相关claims聚合、Telegram网络扩散与协调叙事分析。

### 4.2 数据硬限制

[OSoMe官方记录](https://zenodo.org/records/14189193)当前Restricted；2026-09-09政策要求合资格研究机构邮箱申请，每研究者每天一个数据文件。其[论文](https://arxiv.org/html/2411.10609)提供26个operation、平台核实IO账号及control，不是逐帖谣言真假、逐帖叙事归属或因果来源gold。完整账号timeline包含非campaign帖子，control也可能含未识别IO。

[FakeCTI官方数据](https://zenodo.org/records/17248748)已于2025-10发布，Open、CC-BY4.0、单CSV约5.1MB；原文报告12,155文章、43campaign。不能因代码README仍写“will contain”而宣称数据未发布。本轮未成功逐字段解析CSV，社会网络字段只能称未核实，不能说已证实缺失或存在。

不能把两套数据凭语义匹配拼成“同一谣言的真假+传播网络+协同归属”gold。需要合法完整数据与明确额外标注，且不能仅以LLM自动打标后用同类LLM评测。

**当前决策：独立任务形态较强，但不建议现在立题，数据阻碍比A更大。**

## 5. 候选C：流式重复谣言事件的共享核查与人工预算优化

优化单位是共享核查任务，而不是每个样本送哪个reader：多个帖子是否可以共用一次核查，何时必须拆分任务，有限人工预算先处理哪些事件。

LLM判断语义相关与核查结论可复用边界；传播信息刻画事件增长与跨社区扩散。理想输出为共享任务集合、复核队列与覆盖/成本，不声称真实干预造成传播下降。

[MultiClaim v2](https://zenodo.org/records/15413169)有大量post↔checked claim对应、timestamps和veracity信息，但机构申请、非商业科研限制、禁止重新分发；没有已核实社会传播图、真实核查成本和队列收益gold。对应关系也不意味着原判词可无条件复用。

[PNAS2025复现数据](https://doi.org/10.7910/DVN/K0RQTM)已核实unrestricted、CC-BY-NC-SA4.0，约5.64GB；README提供15分钟单帖engagement时序和post/note metadata，但没有证明正文、传播边或expert truth齐备。作者估计的treatment effects不能直接作为新调度策略的真实收益gold。

PHEME/MultiClaim/Community Notes来自不同对象，不能拼成完整联合gold；否则贡献退化为claim retrieval+启发式调度或人为utility，接近已经失败的旧路线。

**当前决策：条件备选，不启动。需要新数据建设承诺，不能仅靠现成基准完成。**

## 6. 为什么没有推荐普通澄清生成、溯源或核查优先级

- [Good Advisor for Source Localization，IJCAI2025](https://www.ijcai.org/proceedings/2025/326)已用LLM评论表示、传播/用户表示及融合进行谣言源定位；普通LLM+graph溯源不足。
- [Supernotes，WWW2025](https://arxiv.org/html/2411.06116)已有多note生成、helpfulness建模、候选选择与真人偏好评价；偏好不等于信念改变。
- [COMMUNITYNOTES，EACL Findings2026](https://aclanthology.org/2026.findings-eacl.71/)已有104k posts的helpfulness/reason预测。[作者仓库](https://github.com/ruixing76/Helpfulness-FCExp)明确数据需申请，MIT代码许可不是数据许可。
- [AI Fact-Checking in the Wild，2026预印本](https://arxiv.org/html/2604.02592v2)已有真实部署LLM notes及证据不足不写note的triage；提交时机/曝光会混淆helpfulness比较。
- [Request a Note，CHI2026原文](https://arxiv.org/html/2509.09956v2)有核查请求研究，但原帖需另取，misleadingness为GPT proxy，不能当专家truth。
- [Fact-Checking Comments Precede Community Notes，2026-09最新版](https://arxiv.org/html/2509.11052v2)分析评论核查意图与时间。不能继续沿用旧Commenotes生成版摘要；FC意图不证明纠正正确。
- [CrowdNotes+](https://arxiv.org/html/2510.11423)与[GitSearch](https://arxiv.org/html/2602.08945)进一步覆盖分层note评价、证据/搜索和生成；本轮由独立检索分支核查，完整资源可用性仍需另审。
- [FEVER2024 check-worthiness论文](https://aclanthology.org/2024.fever-1.27/)已有LLM规则理解与优先级排序；普通排序不够形成新主线。

## 7. 与用户讨论时应该明确的问题

不是请用户在几个已经成立的好题中选一个。本轮尚未达到该状态。

需要澄清的是研究类型：
- 如果“不能只提高鲁棒性”针对调参数/改损失，但允许研究可证明的安全属性，则A可以继续接受严格查重和边界审查。
- 如果不希望第二工作以抗操纵/稳定性为目标，即使有形式化贡献也不接受，则A应退出。
- 如果希望从检测走向谣言活动发现或核查治理，B/C更符合任务升级，但需接受机构申请和人工联合标注，而不是保证现成公开数据开箱完成。

这不是放宽社会谣言或UMER联系，而是确定“希望升级到什么完整任务”，避免继续围绕局部问题无限筛选。
