# SES-v1 P0 方法级近邻审查

- 核查执行：两个子代理分组核查（A 组 1–5，B 组 6–9），执行者汇总；**全部意见为 provisional**，未逐篇人工复核原文。
- 核查级别含义：正文 = 读到 HTML 全文；官方摘要 = 仅出版页摘要；元数据 = 仅题名出处；FULLTEXT_UNRESOLVED = 合法途径未获全文。
- 候选问题：LLM 读取真实社交线程时，(a) 同源复述（同一上游被多回复转述）是否被重复累计为事实支持；(b) 有效独立纠错（少数正确反证）能否被保留并促成正确更新；主张把文本相似 / 来源归属 / 来源依赖 / 事实可靠性四个概念分开建模。

## 威胁排序与结论

1. **Whose Facts Win（最强威胁）**：已在合成条件中分离"重复×来源归属"，并实证同源重复被当作事实支持。它证明了**现象**，但未在真实社交线程上建模**结构**（RT 链/共享 URL/跨域转述），未评估**纠错保留**。
2. **Speaker-Free Floor**：真实文本插入，区分重复条数与说话人数；纯测量。
3. ProvenanceGuard：来源归属与文本支持分开（cross-source conflation），无依赖建模。
4. 其余各篇不直接覆盖。

**综合判定**：四概念分离的完整主张与两项性质（同源复述不重复计数、独立纠错保留）在 9 篇中无同时覆盖；但"同源复述不应计为独立支持"的现象级主张已被 #1 与 #9 大幅占位——我们不能再以"发现该现象"为贡献，只能以**真实线程上的结构化机制 + 纠错保留**为贡献。#4/#6 全文受限， nearest_work_exclusion 记 UNRESOLVED 而非 SUPPORTED。

## 机制假设（最多两条，均可证伪）

### H1 依赖感知计数（dependency-aware counting）
- 输入约束：真实社交线程快照（源帖 + 截点前回复树），每回复的可核上游信号（显式 RT/引述前缀、共享展开 URL、原生 annotation 链接 position）。
- 机制位置：聚合层的计数规则——按"可核共同上游"分组后组内去重计数，而不是逐条计数或文本相似去重。
- 为何不是去重/提示拼装：去重基线是文本相似或精确重复；H1 的分组信号是**上游结构**（同一 BBC 链接、同一 RT 链顶点、跨语言同源引述），P0 深查显示它与文本相似度不同（同一 URL 簇内文本可各异；同文 RT 无 URL）。
- 最强简单基线：规则去重（共享 URL / RT 前缀归并）必须作为基线；若规则去重已达到 H1 全部收益，H1 失败。
- 推翻条件：同 token/同覆盖率下，依赖分组聚合与朴素多数或规则去重无显著差异；或依赖分组信号与文本相似度高度共线（相关性 > 0.9 类水平），即"依赖"不提供文本相似之外的信息。

### H2 可溯源纠错保留（traceable-correction retention）
- 输入约束：同上；树内存在少数"有效独立纠错候选"（断言式或引用式），多数行为同源回声。
- 机制位置：聚合层对纠错行的加权/保留规则——对与源帖不同上游、且在树内获得独立响应（如 028-R004 对 R003 的确认）的纠错行做保留加权。
- 为何不是提示拼装：不修改 reader prompt；只改变输入行的选择与权重，读者仍是冻结 reader。
- 最强简单基线：均匀给所有反驳词命中行加权（不经依赖判断）；以及"全部忽略回声行"。
- 推翻条件：纠错保留增益在消融"依赖判断"后不下降（说明增益全部来自反驳加权或减回声）；或纠错行识别实际上依赖最终 V 标签（标签泄漏）；或 false→correct 提升以 true→wrong 显著上升为代价。

两条假设共享同一评测底座（P0 深查的树/URL/annotation 结构），可在一轮小试验中同测。
