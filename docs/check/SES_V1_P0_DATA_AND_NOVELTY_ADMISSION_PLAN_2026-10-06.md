# SES-v1 第一轮计划：数据与创新准入审查（P0）

- 日期：2026-10-06。
- 方向：虚假社会共识下的依赖感知社会证据安全。
- 临时记录代号：`SES-v1`（社会证据安全），仅用于区分资产，不代表已有新方法。
- 依据：[R4 调研与方向选择](LLM_SOCIAL_RUMOR_DIRECTION_DECISION_R4_2026-10-06.md)。
- 本轮目标：确认可检验的剩余问题和现实数据入口，为下一轮小规模标注／机制试验设计提供证据；不是训练、reader 实验或论文级验证。
- 授权边界：实施本 P0 的文献核查、现有数据只读审查、有限公开资源获取、CPU 审计及报告；不自动进入 P1。

## 1. 独立执行规范

**具体执行规范和要求需要从 [UMER_BCR_RESEARCH_HANDOFF_2026-10-02.md](../../UMER_BCR_RESEARCH_HANDOFF_2026-10-02.md) 中检索。**

必须提取并遵守 LOCAL／SERVER、模型使用、连接入口、事件隔离、环境版本、历史结果只读、人工确认和失败路线规则。交接首页的 M1-E 状态已经过时，BCR 最新正式关闭结论优先；不能恢复 BCR、CR-TSER 或执行原 M2。

执行采用简体中文和 PowerShell 7+；检索先枚举候选再查内容。每条递归检索限时不超过 60 秒，候选路径最多 50、内容结果最多 20，超限收窄；排除 `.git`、`.zcode`、依赖、缓存、构建和日志目录。不得扩大到盘根、用户目录或任意缓存。

不写 C 盘、不安装依赖、不改全局环境、不加载正式 reader、不轮询 GPU、不生成攻击 payload、不操作真实社交平台。仅对获授权的离线资源审查。缺凭据、付费、数据许可或关键权限时停下相关步骤，报告精确缺项；不使用 mock、占位凭据或猜测值继续。

## 2. 本轮要回答的问题

1. 排除普通去重、来源归属检查、重复不变训练和拒判后，还剩下什么可证伪的具体方法问题？
2. 现有真实社交线程是否能找到可核验的共同来源复述，并同时包含独立有效的少数纠错材料？
3. 能否将文本相似、来源归属、来源依赖、事实可靠性与当前证据充分性分开记录？
4. 下一轮是否值得设计人工双人标注与冻结 reader 小试验？

本轮不回答模型是否已被重复材料带偏，也不估计防御增益；没有模型推理，不能据数据审计宣称失效已复现。

目标始终是两项性质同时成立：同源复述不重复累计为事实支持；有效独立反证仍能促成正确更新。不能通过屏蔽全部评论或永远拒判取胜。

## 3. 任务 A：版本、许可与真实数据入口

### 3.1 接手核验

记录实际工作区、HEAD、分支、工作树状态和目标远端；远端应为 `Ethan-Martinez-creater/UMER_LLM`。本轮参考基线为 `d71991dd9745a910e94ca91398d0b871a7ffda7f`，执行时核实当前版本，不强制退回历史提交。

用户现有删除／未跟踪文件保持不动；不执行 reset、clean、stash、rebase 或批量恢复。不自动拉取并覆盖本地改动。差异不阻塞独立审查时如实记录；相关输入变化影响结论时暂停该步骤。

### 3.2 定位顺序与范围

1. 先读 `resources/resource_manifest.md`，并从交接文档定位 PHEME 原始数据入口。
2. 只查看清单明确指向的项目子目录。需要服务器时，仅通过手册规定入口，对明确 PHEME 数据路径只读访问；不得做服务器全树搜索。
3. 若现有数据没有 veracity annotation，可以从官方 PHEME veracity 公开资源获取一个不超过 100 MB 的原始压缩包，保存在工作区新目录 `local_assets/ses_v1/p0/`。已有同名文件先检查，不覆盖；记录下载 URL、版本／发布日期、字节数与 SHA256。
4. 下载前核查元数据、许可和大小。未知大小、超过上限、需要登录／付费、许可无法核实，记 `NOT_READY` 或依赖阻塞；不能换不明镜像。解包前检查绝对路径和 `..` 等路径穿越，只在新目录读取／安全解包，不执行下载代码。
5. 最多获取 12 个候选例涉及的公开引用页面，保存于上述本地资产目录；记录请求时间、来源和内容哈希。不做全站抓取或在线新闻检索 API 调用。网页可访问不等于具有发布内容的许可。

官方数据入口：

- [PHEME veracity](https://figshare.com/articles/dataset/PHEME_dataset_for_Rumour_Detection_and_Veracity_Classification/6392078)。
- [PHEME 原始数据定义参考](https://arxiv.org/html/1806.03713v1)。

所有原文、原始包、逐用户正文和本地缓存不进入 Git。仅记录公开引用链接和必要哈希。若缺入口，报告已查范围，不改查其他盘或用户目录。

### 3.3 资产检查

在任何人工挑例前，核实 source、reactions、tree、annotation 的真实字段，建立 R 与 V 的独立映射，统计时间戳、作者／回复关系、URL 和原始标注覆盖、冲突、重复。

- `R` 是 rumour/non-rumour；`V` 是 true/false/unverified。
- 依据原始定义解析，不从线程文本或 processed 二分类猜 `V`。
- non-rumour 不补 true；unverified 不补 false 或早期 unknown。
- 缺作者／URL／parent 就记 missing，不替换为 thread ID 或文本推断值。
- 最终 `V` 只作事实结果参照，不当作逐截点证据充分性标签。

记录许可适用范围：数据注释许可、原社交内容权利与派生统计发布权限分开。权限未确定的逐样本信息仅保留本地，不推送。

## 4. 任务 B：固定 60 条线程的可标注性审查

### 4.1 选样规则（不得先看案例再挑）

只从真实可读、有原生 `V` 且源帖／回复可映射的 PHEME rumour 线程选择，目标 `true=20、false=20、unverified=20`，总计 60。

固定选样盐为 `SES-v1-P0-20261006`。对每个 V 类别：

1. 将新闻话题按话题名 UTF-8 字节的 SHA256 排序。
2. 各话题内按 `SHA256(盐|数据版本标识|topic|source_id)` 排序线程。
3. 按话题顺序轮转，每轮每话题取下一条，直到该类别 20 条或池耗尽。

不足时全取并报告缺额，不用其他标签补足，不改选样盐。公开数据版本标识固定后记录哈希。该筛查分层使用最终 V，不是部署特征或正式评测抽样。

60 是探索上限，不是统计功效保证。原 source thread 也不必然是独立事实主张：记录跨线程相同主张／复制来源风险，不能把 60 条称为 60 个独立事实事件。

manifest 在阅读正文前冻结。选中线程没有重复或纠错也是有效审计结果，不以“无用”为由替换。全部选中线程永远作为发现／开发资产，后续不得进入最终确认评测。

### 4.2 时间边界

为后续因果截点评测审计 `15、60、360` 分钟的真实可用回复与出处，不强制复用历史 BCR 的输入或标签。

- 无候选、时间缺失、父子时间冲突分别报告。
- 360 分钟之后的材料可用于理解档案可得性，但标为 `AFTER_CUTOFF`，不得当作当时输入。
- 当前可读的网页不自动代表历史截点已存在且内容相同。发布时间、存档版本、更新／纠正记录不可核时标为 `TEMPORAL_AVAILABILITY_UNKNOWN`。
- 是否事实正确、是否被某材料支持、该材料当时是否可用分别记录。

### 4.3 观察编码（不是训练 gold）

为每条线程记录以下暂定审查项及原文定位：

| 维度 | 可用状态 | 限制 |
|---|---|---|
| 文本复述 | 明确重复／改写候选／无／未知 | 仅相似不能证明依赖 |
| 来源归属 | 明确引用／未明确／无法访问 | 不等于来源独立或可靠 |
| 来源依赖 | 可核共同上游／可核不同上游候选／未知 | 同 URL 可含不同材料；不同域名可能转载同一来源 |
| 内容角色 | 事实依据候选／意见或附和候选／纠错候选／其他／未知 | support/deny 不等于事实／观点类型 |
| 支持关系 | 支持／反驳／不足／未知的审查意见 | 必须绑定明确命题、材料位置和核验理由 |
| 时间可得性 | 截点前可核／截点后／未知 | 不能用最终 veracity 代替 |

“可核不同上游候选”不称绝对独立；无法排除共同上游时保留 uncertainty。纠错只有明确可核材料才能列为有效候选，不能只因其符合最终 V、账号权威或 stance 为 deny。

执行智能体可以做证据审查笔记，但不是独立人工标注员，不能称 human gold、不能产生 κ、一致性或正式依赖真值。不得让另一模型投票把这些意见升级为 gold。

### 4.4 候选例核查

在固定 60 条中最多深入核查 12 条，按 manifest 顺序取具备所需材料的候选，不重抽 60 条。每条给：

- 脱敏内部 ID、原数据定位与哈希。
- 同源复述及其共同上游的证据；若没有，明确写无／未知。
- 纠错命题、支撑材料、上游链和相对源帖时间。
- 哪些记录依赖最终真值、哪些能从当时材料核实。
- 不能核实之处、后续双人标注所需信息。

最多访问 12 个额外公开引用页面；某例用多个页面则占多个额度。超额需求记录，不擅自增加预算。无需生成新重复评论或攻击文本。

同时报告全部 60 条的比例、缺失分布和被深入核查条件，不能只展示成功例。

必要时最多补充 3 篇直接近邻，总上限 12。若假设涉及分组读取、隔离聚合或认证，必须将 [RobustRAG 更新原文](https://arxiv.org/html/2405.15556v2)计入补充近邻，且不能误标主会身份。

不得执行论文 demo、配置新 API key 或下载模型。全文受限时使用合法作者版本／机构版本；找不到则标 `FULLTEXT_UNRESOLVED`，不绕过权限，不把摘要没提某机制当作不存在。

### 5.2 对照表与允许的结论

每篇至少列：正式身份、版本日期、核查级别、任务、依赖／重复定义、是否处理来源不完备、是否评估有效少数纠错保留、方法与强基线、我们可能新增什么、节号／证据 URL。

将作者明确指出的局限与执行者推导的问题分开。不把 citation、source attribution、独立性、事实正确性、模型偏好混为一谈。

提出最多两条可证伪方法假设，每条写出：输入约束、机制位置、为何不是去重／来源提示拼装、最强简单基线、什么结果会推翻它。没有可信剩余机制就明确写“尚无”，不强行发明架构。

关键全文未核实使差异无法判断时，创新项为 `UNRESOLVED`；“没查到完全同名方法”不能记通过。

## 6. 任务 D：准入判决与下一轮草案

### 6.1 各维度独立判定

对 `asset_access`、`license`、`native_label_mapping`、`temporal_traceability`、`dependency_observability`、`correction_observability`、`nearest_work_exclusion`、`distinct_falsifiable_hypothesis` 分别记录：

`SUPPORTED_FOR_DESIGN / NOT_READY / UNRESOLVED / BLOCKED`

每项必须附路径／表格行／文献定位，不能只有布尔值。模型有效性固定为 `NOT_TESTED`；gold 状态固定为 `PROVISIONAL_AUDIT_NOT_GOLD`。

### 6.2 送下一轮设计评审的最低条件

以下是本项目发现性筛查门槛，不是论文统计标准，不得看完结果再放宽：

1. 真实 V 映射、数据读取和必要使用权限明确，相关冲突已解释。
2. 60 条目标样本满足或明确报告缺额；准备推荐下一阶段时至少有 40 条可审查且至少 3 个新闻话题。
3. 深入审查范围内至少有 6 条“共同来源复述＋有效独立纠错”暂定配对候选，覆盖至少 3 个新闻话题，其中至少 2 条 V=true、2 条 V=false；其他样本保留作未知／负例对照。
4. 上述候选所需出处在相关截点的可用性有可核依据，不以事后网页替代；依赖与纠错观察可交双人复核，而非仅依赖语义相似、作者身份或最终 V。
5. 关键近邻的差异已有可追溯证据；若全文缺失阻碍判断则不满足。
6. 至少一条具体可证伪的剩余机制假设，并能设计同 token／同覆盖率比较及有效纠错保留评测。

通过也只表示值得设计 P1，不表示 candidate pair 已成为 gold、模型问题成立或创新获得确认。若配对不足，报告是哪种资料缺失，不以 synthetic／LLM gold 补数。

### 6.3 总判决

- `SES_P0_READY_FOR_P1_DESIGN`：上述条件满足，提交下一轮小规模人工核验／机制试验设计草案后停止，等待审批。
- `SES_P0_NOT_READY`：数据、许可、时间或全文关键证据不足；明确最小缺项及是否现实可补。不启动模型，不自动改为研究别的任务。
- `SES_P0_NOVELTY_BLOCKED`：有直接实质重合，或仅剩去重／提示／拒判拼装；附准确对照，不自动转备选。
- `SES_P0_INFRASTRUCTURE_PAUSE`：凭据、连接、依赖或权限阻塞；只暂停依赖步骤，完成不依赖它的文献／报告工作，不把基础设施问题当科研 NO_GO。

存在多个问题时记录每项；总判决优先报告实际阻塞，不能用一个标签掩盖其他缺陷。

### 6.4 下一轮草案仅需一页

写清：候选样本与永久发现集隔离、拟请两名独立人工核验者审查的定义、预计标注量、可靠性与裁决设计、冻结 reader 的实验臂、token／位置／截断控制、覆盖率匹配、事件／同主张分组统计、开发集与确认集边界、预算与停止条件。

不假装已有人工核验者；人员和资源尚未落实则写 `PENDING_HUMAN_RESOURCE`。不在本轮执行人工招募、付费、reader 推理、attack generation 或训练。既有 reader contract 不能擅自改为量化／新 scoring；是否需要新协议由下一轮审批决定。

## 7. 输出与验证

可公开派生输出统一放在 `docs/check/ses_v1/p0/`：

1. `P0_ASSET_AUDIT.json`：版本、读取位置、许可、SHA256、字段覆盖、冲突和资源阻塞；不含凭据。
2. `P0_MANIFEST.csv`：固定抽样顺序、匿名线程 ID、topic、R、V、输入哈希和可用性；仅许可允许的派生字段。
3. `P0_OBSERVABILITY.csv`：全部固定线程观察状态、缺失和引用审查证据；字段显式标 `provisional`。
4. `P0_CASE_AUDIT.md`：最多 12 条深入审查记录、时间／出处限制；不复制用户原文，不泄露个人信息。
5. `P0_NEAREST_WORKS.md`：方法级近邻表、核查级别和最多两条机制假设。
6. `P0_VERDICT.json`：逐项判决、证据索引、总状态、未解决项，明确无模型实验与正式新 gold。
7. `P0_NEXT_STAGE_DRAFT.md`：一页草案；若阻塞，写最小补齐项而非假定已通过。
8. `P0_REPORT.md`：不超过 1500 中文字符的总结，链接完整表格；报告覆盖分母、选样限制、失败证据和下一轮建议。
9. `P0_VALIDATION.json`：排序重放、manifest 唯一性、R/V 语义、样本数／缺额、cutoff 状态、schema 和报告链接检查结果。

原始正文、完整个人 ID、网页快照和私有映射仅在 `local_assets/ses_v1/p0/`，不提交。发布权限不足时相关派生文件也保留本地，公开报告写聚合统计和限制，不以删掉敏感字段掩盖审计无法复现的问题。

允许为本 P0 新建轻量 CPU 审计脚本与测试，限定 `scripts/ses_v1/p0/` 和 `tests/ses_v1/p0/`，不修改现有 reader／训练代码，不创建推理入口。使用现有依赖；测试可以使用最小合成 fixture 验证解析逻辑，但不得将测试 fixture 作为科研样本、替代真实缺失数据或进入输出 manifest。

验证需重放固定抽样、核对数据哈希／版本及 CSV／JSON schema，检查未知状态未变成真值、截点后材料未进入截点前候选、没有将正文和凭据放入待提交文件。验证失败如实报告，不能写“全部通过”。
